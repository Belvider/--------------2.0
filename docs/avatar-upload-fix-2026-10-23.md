# Завантаження фото профілю

На production-сайті відтворено збій: вхід технічного користувача повертає 200, завантаження невеликого PNG — 500. Перевірка не використовує особисті фото чи чужі акаунти; локальні дані технічного акаунта виключені з Git.

## Виправлення

- Приватні URL `/uploads/*` та `/api/uploads/*` у `UserAvatar` обходять оптимізатор Next Image. Зображення запитує браузер із cookie; перевірка авторизації для файлів збережена. [Next Image](https://nextjs.org/docs/app/api-reference/components/image).
- Спільна перевірка формату, порожніх файлів і розміру працює в браузері й API. Ліміт фото — 4 MiB із запасом на multipart у межах обмеження запиту Vercel 4,5 MB. [Vercel Functions limits](https://vercel.com/docs/functions/limitations).
- Помилки мережі, HTML замість JSON і помилки сервера відображаються в профілі. Керування знову доступне після невдалої спроби, той самий файл можна вибрати повторно.
- Паралельні зміни блокуються в компоненті; після успішного збереження фото одразу з’являється й сторінка оновлюється.
- Унікальні назви файлів запобігають колізіям. Помилка очищення старого файла не перетворює вже збережене фото чи видалення на помилку. Якщо запис профілю не вдався, новий файл прибирається, попереднє фото зберігається.
- Відсутність постійного сховища повертає зрозумілу відповідь 503. Деталі сховища, токени та дані бази не потрапляють у повідомлення користувача.
- Для підключеного Blob-сховища на Vercel дозволена автентифікація OIDC через контекст запиту. Запис на локальний диск Vercel не використовується.

## Перевірка

127 автоматичних тестів пройшли, зокрема сценарії авторизації, формату й розміру, повторної спроби, збою сховища/бази, очищення файлів, прямого відображення захищеного фото та OIDC без токена в env.

Production-збірка пройшла. У Chrome на ширинах 390 та 1440 пікселів перевірено справжні компоненти після hydration із тестовим API: невдала спроба → повторний вибір того самого файла → відображення фото → видалення. Браузер передає cookie без оптимізатора, а неавторизований запит до файла отримує 401. Переповнення, помилок hydration і виконання не виявлено.

Приватні результати перевірок і скрипт production-проби: `reports/avatar-fix-2026-10-23/`. У Git не додаються паролі, cookie та ідентифікатори технічної сесії.

## Підключення сховища, якщо production повертає 503

1. У проєкті `pineapplestudy` відкрити **Storage → Create Storage → Blob → Continue**.
2. Вибрати **Private** і **Create a new Blob store**.
3. У сховищі **Projects → Connect to Project** підключити `pineapplestudy` до **Production**. Для існуючого підключення — **Update Project Connection**.
4. Виконати redeploy production і повторити пробу.

Нові підключення за замовчуванням використовують `BLOB_STORE_ID` та автоматично виданий OIDC-токен. Значення токенів не потрібно копіювати в чат. [Інструкція підключення](https://vercel.com/docs/vercel-blob/using-blob-sdk#getting-started), [OIDC](https://vercel.com/changelog/vercel-blob-now-supports-oidc-authentication).
