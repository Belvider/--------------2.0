# Перенесення наявного наповнення на 2pine

GitHub і Vercel публікують код та файли з `public/`. Навчальні матеріали,
користувачі, адміністратор, тести й прогрес зберігаються окремо в PostgreSQL.
Створення таблиць через міграцію не переносить їхнє наповнення.

Інвентаризація локальної бази від 18 жовтня 2026 року: 2 користувачі,
12 брендів, 32 категорії, 73 модулі, 290 запитань, 15 записів прогресу,
17 записів активності, 3 спроби тестів і 3 сертифікати. Інструмент перенесення
охоплює всі 16 моделей Prisma, зокрема налаштування й журнали.
У `public/uploads/` також є 2 фото загальним розміром 71 340 байтів.

## Підготовка доступу

Потрібні доступ до production-бази Neon, підключеної до Vercel `2pine`,
та приватне сховище Vercel Blob для завантажених фото й медіа.

Для роботи через Codex можна під'єднати інтеграції Neon і Vercel.
Для локального запуску інструментів використовується приватний файл
`.env.transfer.local`, який ігнорується Git:

```text
SOURCE_DATABASE_URL="URL локальної бази"
TARGET_DATABASE_URL="Direct URL production-бази Neon"
BLOB_READ_WRITE_TOKEN="Токен приватного Blob-сховища"
```

`SOURCE_DATABASE_URL` уже заповнено з локального `.env`, якщо файл підготовлено
помічником. Не змінюйте робочий `.env` на production URL. Значення доступу
залишаються в локальному файлі; цей файл і резервні копії не завантажуються
в GitHub.

Direct URL можна скопіювати з Neon Console → Connect, вимкнувши connection
pooling. Це має бути база, підключена до production проєкту `2pine`.

Приватне сховище створюється у Vercel → `2pine` → Storage → Create Storage →
Blob → **Private**. Назва, наприклад `2pine-uploads`. Підключіть його до
Production проєкту `2pine`; Vercel надає `BLOB_READ_WRITE_TOKEN`.
Після зміни production-змінних потрібен Redeploy.

## Перенесення бази

Локальна резервна копія перед перенесенням:
`reports/server-transfer-2026-10-18/local-before-transfer.dump`.
Перед роботою запустіть локальний PostgreSQL.

Попередній перегляд без змін у серверній базі:

```powershell
node --env-file=.env.transfer.local scripts/transfer-database.mjs
```

Перевірте, що `conflicts` порожній. Якщо інструмент знайшов різні записи
з однаковими природними ключами, наприклад два акаунти з одним email і
різними паролями, він зупиниться. Такі розбіжності потрібно вирішити окремо;
наявні записи в Neon автоматично не перезаписуються.

Застосування підготовленого перенесення:

```powershell
node --env-file=.env.transfer.local scripts/transfer-database.mjs --apply
```

Перед записом інструмент створює й перевіряє локальну резервну копію поточного
Neon у `reports/`. Потім в одній транзакції додає дані, перевіряє результат і
налаштовує послідовності ID. Усі записи, які існують лише онлайн,
залишаються. Конфлікти числових ID обробляються з перенесенням зв'язків;
невідомі посилання зупиняють імпорт. Повторне перенесення незмінених даних
не створює дублікатів.

Переносяться наявні хеші паролів і ролі. Локальний адміністратор зможе
входити на сервер із тим самим паролем; інструмент його не скидає.
`prisma:seed`, очищення таблиць і reset під час цього перенесення не потрібні.

## Перенесення фото та медіа

Попередній перегляд локальних файлів:

```powershell
node --env-file=.env.transfer.local scripts/transfer-uploads.mjs
```

Копіювання до приватного Blob-сховища:

```powershell
node --env-file=.env.transfer.local scripts/transfer-uploads.mjs --apply
```

Інструмент зберігає шляхи `/uploads/...`, пропускає вже перенесені однакові
файли й зупиняється перед записом, якщо за тим самим шляхом є інші байти.
Файли на сервері не видаляються й не перезаписуються. Звіти з кількістю
файлів і розміром зберігаються локально в `reports/`.

Після розгортання нового адаптера доступ до `/uploads/...` мають лише
авторизовані користувачі, а відповідь не кешується публічно.

## Перевірка

Після фактичного перенесення перевірте кількість модулів і запитань у Neon,
увійдіть акаунтом адміністратора, відкрийте каталог, навчальний модуль,
тест, профіль і фото. Сторінки потрібно перевіряти за вмістом, оскільки
HTTP 200 у Next.js може містити помилку серверного рендерингу.

Саме додавання цих інструментів у GitHub ще не переносить приватні дані.
Факт перенесення підтверджують звіт імпорту та перевірка production-сайту.

Після перенесення курси, користувачів і призначення редагуйте в онлайн-
адмінпанелі, яка працює з Neon. Зміни коду далі публікуються через GitHub
і автоматичний деплой Vercel. Локальна база залишається окремою копією.

Офіційні інструкції:
[підключення до Neon](https://neon.com/docs/connect/connect-from-any-app),
[створення та підключення Vercel Blob](https://vercel.com/docs/vercel-blob/using-blob-sdk).
